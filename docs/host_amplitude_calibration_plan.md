# 上位机幅度校准功能计划

## 目标

先实现纯上位机幅度校准，不改下位机协议和固件。上位机通过已知单音信号采集多个校准点，生成校准因子文件；后续实测频谱显示时导入该文件，并在上位机侧对显示功率做补偿。

第一版聚焦绝对幅度校准：

- 用户接入已知频率、已知功率的单音信号。
- 上位机完成当前频谱扫描后自动找峰。
- 用户输入该单音在仪器输入端的真实功率。
- 上位机自动切换多个 RBW 档位并分别采样峰值。
- 多个频点重复上述流程。
- 导出校准文件，下次启动或手动导入后用于频谱补偿。

## 当前实现基础

当前上位机已有可复用能力：

- 频谱数据保存在 `_spectrumData`，点结构为 `FlSpot(freqHz, powerDbm)`。
- 扫描完成后 `_completeSweepAssembly()` 会更新显示频谱，并在自动峰值模式下更新 marker。
- RBW 档位可通过 `rbwMode` 切换，当前代码支持 `1 kHz`、`10 kHz`、`30 kHz`、`100 kHz`、`300 kHz`、`1 MHz`。
- 已有截图和相噪 CSV 导出逻辑，可复用 `Directory`、`File`、时间戳文件名和 `InfoBar` 成功/失败提示风格。

## 校准数据模型

建议校准文件使用 JSON，便于保存元数据和后续扩展。

```json
{
  "schema": "pusu_host_amplitude_calibration",
  "version": 1,
  "created_at": "2026-05-26T15:30:00+08:00",
  "device": {
    "name": "PuSuSA",
    "serial": "",
    "note": ""
  },
  "reference_plane": "rf_input",
  "source": {
    "model": "",
    "cable_loss_db": 0.0,
    "external_atten_db": 0.0
  },
  "points": [
    {
      "frequency_hz": 100000000.0,
      "reference_power_dbm": -20.0,
      "samples": [
        {
          "rbw_hz": 10000.0,
          "measured_power_dbm": -23.2,
          "correction_db": 3.2,
          "peak_frequency_hz": 100001000.0,
          "timestamp": "2026-05-26T15:31:00+08:00"
        }
      ]
    }
  ]
}
```

核心计算：

```text
correction_db = reference_power_dbm - measured_power_dbm
display_power_dbm = raw_power_dbm + correction_db
```

第一版按 `frequency_hz + rbw_hz` 存表。补偿时选择当前 RBW 对应的校准曲线，再按频率插值。

## 校准流程

### 1. 进入校准模式

在上位机增加“幅度校准”入口，建议放在现有幅度/Marker 相关区域或顶部工具栏。

校准模式需要显示：

- 当前校准文件状态：未加载、已加载、已修改。
- 当前待校准频点列表。
- 当前信号源真实功率输入框。
- 当前采样 RBW 档位选择。
- 单点采样、自动多 RBW 采样、导出、导入、清空按钮。

### 2. 添加一个校准点

用户操作：

1. 设置频率范围，使已知单音位于当前频谱内。
2. 输入该单音真实功率。
3. 点击“采集当前点”。

上位机操作：

1. 触发一次当前 RBW 扫描。
2. 在扫描完成后从 `_spectrumData` 找峰值。
3. 记录峰值频率、峰值功率和参考功率。
4. 计算该 RBW 的校准因子。

### 3. 自动多 RBW 采样

用户输入一次真实功率后，上位机自动遍历 RBW 档位：

```text
1 MHz -> 300 kHz -> 100 kHz -> 30 kHz -> 10 kHz
```

是否包含 `1 kHz` 建议做成可选项。`1 kHz` 扫描时间长、稳定性要求高，适合第二阶段或手动勾选。

每个 RBW 档位执行：

1. 暂停连续扫描。
2. 设置 RBW/VBW。
3. 应用测量配置。
4. 发起单次扫描。
5. 等待扫描完成。
6. 找峰并记录样本。
7. 进入下一个 RBW。

采样完成后恢复用户原本的 RBW、VBW、连续扫描状态。

### 4. 多频点校准

用户可重复添加多个频点，例如：

```text
50 MHz, 100 MHz, 200 MHz, 500 MHz, 800 MHz, 1 GHz, 1.2 GHz, 1.5 GHz
```

第一版不强制频点间隔，但导出前应提示：

- 频点少于 2 个时只能做固定 offset，不能做频率插值。
- 某个 RBW 缺少样本时，该 RBW 只能 fallback 到最近可用 RBW 或不补偿。
- 频点不单调时导出前自动排序。

## 补偿应用策略

### 第一版

实时显示时，在 `_spectrumData` 写入前或写入后统一补偿。

建议在显示层补偿，而不是改动原始串口解析：

- 保留原始扫频点，便于调试和导出 raw 数据。
- 图表、Marker、峰值搜索使用补偿后的数据。
- UI 明确显示 `CAL` 或 `UNCAL` 状态。

查表规则：

1. 优先使用当前 RBW 完全匹配的校准曲线。
2. 在该 RBW 曲线内按频率线性插值。
3. 超出校准频率范围时使用最近端点，并给出 `extrapolated` 状态。
4. 当前 RBW 没有曲线时，第一版建议不补偿，并显示 `RBW uncalibrated`。

### 后续扩展

可增加跨 RBW fallback：

- 选择最近 RBW 曲线。
- 或使用同一频率下不同 RBW 的平均校准因子。

但第一版建议保守处理，避免用户误以为所有 RBW 都已校准。

## 导入和导出

### 导出

默认保存目录可复用当前截图目录，文件名建议：

```text
amplitude_calibration_YYYYMMDD_HHMMSS.json
```

导出成功后用 `InfoBar` 显示完整路径。

### 导入

导入时校验：

- `schema` 是否为 `pusu_host_amplitude_calibration`。
- `version` 是否支持。
- `points` 是否非空。
- 每个 sample 是否包含 `rbw_hz`、`measured_power_dbm`、`correction_db`。
- 频率、功率、校准因子是否为有限数值。

导入成功后：

- 更新校准状态为 `CAL`。
- 显示文件名、创建时间、频点数量、覆盖 RBW 档位。
- 允许用户启用/禁用补偿。

## 需要提前确认的问题

1. “输入已知功率”指的是信号源面板输出功率，还是扣除线缆损耗、外部衰减器后的仪器输入端功率？建议统一为仪器输入端功率。
2. 自动采样到底使用五个 RBW 还是当前代码已有的六个 RBW？建议默认五个：`10 kHz` 到 `1 MHz`，`1 kHz` 可选。
3. 峰值搜索是在全 span 内找最高点，还是围绕用户输入/marker 附近搜索？建议第一版支持全局峰值，但加入“搜索窗口”选项，避免强杂散被误选。
4. 校准时是否固定 LNA、衰减器、VGA 状态？第一版建议记录当前状态，但只保证同一状态下有效。
5. 是否需要自动恢复校准前的测量配置？建议必须恢复，避免校准流程结束后用户界面状态跳变。

## 执行计划

### 阶段 1：数据结构和文件能力

- 新增上位机校准模型：校准文件、校准点、RBW 样本。
- 实现 JSON 编码和解码。
- 实现导入、导出、校验和错误提示。
- 在 UI 显示当前校准文件状态。

### 阶段 2：单点采集

- 增加校准面板入口。
- 增加真实输入功率输入框。
- 实现从当前 `_spectrumData` 找峰。
- 生成当前 RBW 下的单个校准样本。
- 在面板中展示采样结果和校准因子。

### 阶段 3：自动多 RBW 采样

- 实现校准采样状态机。
- 暂停连续扫描并保存当前测量配置。
- 依次设置 RBW、触发单次扫描、等待完成、找峰、记录样本。
- 采样完成后恢复原配置。
- 处理超时、用户取消、串口断开等异常。

### 阶段 4：补偿应用

- 实现按 RBW 和频率查找校准因子。
- 对显示频谱数据应用补偿。
- Marker、自动峰值、读数使用补偿后数据。
- UI 显示 `CAL`、`UNCAL`、`RBW uncalibrated`、`extrapolated` 等状态。
- 提供补偿启用/禁用开关。

### 阶段 5：验收

- 无校准文件时，显示保持原样并标记 `UNCAL`。
- 导入校准文件后，同一频点读数接近输入真实功率。
- 切换已校准 RBW 后读数稳定。
- 切换未校准 RBW 时不误补偿，并给出提示。
- 重启上位机后可重新导入校准文件继续使用。

## 第一版不做

- 不修改下位机固件。
- 不新增 UART 校准命令。
- 不把校准表写入下位机 Flash。
- 不自动控制外部信号源。
- 不保证不同 LNA、衰减器、VGA 状态之间通用。
- 不做温度补偿和线性度补偿。
