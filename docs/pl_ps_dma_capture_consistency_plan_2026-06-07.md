# PuSuSA PL/PS DMA Capture Consistency Plan

Date: 2026-06-07

Scope: `code/pusu_20260516` PS-side processing baseline. This plan is for the
raw LTC2208 ADC stream path:

```text
LTC2208 ADC -> PL AXI4-Stream -> AXIS FIFO -> AXI DMA S2MM -> PS DDR
```

The work is intentionally split into two stages:

1. Build a controlled single-frame capture path so every DMA buffer is complete,
   bounded, and verifiable.
2. Replace the repeated Simple DMA rearm flow with a continuous DMA strategy for
   narrow-RBW measurements that need true cross-buffer continuity.

## 1. Current Problem

The current hardware/software path lets the PL ADC AXI stream run freely while
the PS repeatedly starts AXI DMA SimpleTransfer requests.

Important current properties:

- `LTC2208.v` samples ADC data and directly generates AXI4-Stream output.
- `PACKET_LENGTH = 4096`, so TLAST is generated by an internal free-running
  packet counter.
- `axis_data_fifo_0` sits between `LTC2208_0/M_AXIS` and
  `axi_dma_0/S_AXIS_S2MM`.
- `axis_data_fifo_0` depth is currently `1024` words.
- `axi_dma_0` is S2MM-only, Simple mode, with `c_sg_length_width = 16`.
- PS-side sweep and phase-noise engines rearm DMA one block at a time.

This means DMA completion only proves that a requested number of bytes reached
DDR. It does not prove that the buffer starts at a known PL packet boundary, nor
that repeated DMA buffers are sample-continuous with each other.

The expected failure mode for narrow RBW is:

```text
DMA block A and DMA block B are both valid blocks,
but they are not adjacent samples in the ADC stream.
The PS DSP path then keeps long FIR/decimator state across this gap,
so invalid block boundaries leak energy into the RBW result.
```

## 2. Stage 1: Controlled Single-Frame Capture

### 2.1 Goal

Guarantee that each DMA buffer is one complete, deterministic ADC capture
window:

- PS arms DMA first.
- PS starts PL capture.
- PL emits exactly `frame_len` samples.
- PL emits exactly one TLAST on the last sample.
- PS validates `frame_id`, `sample_count`, TLAST, overflow, and error status
  before passing data to DSP.

This stage guarantees continuity inside one DMA buffer. It does not claim
continuity between separate DMA buffers.

### 2.2 PL Architecture

Refactor the PL path to separate ADC sampling from controlled AXI transfer:

```text
LTC2208_0
  adc_data/adc_of/adc_clk
    -> adc_capture_axis_0
       -> axis_data_fifo_0
          -> axi_dma_0/S_AXIS_S2MM
```

`LTC2208.v` should keep the ADC LVDS sampling logic and expose:

- `adc_clk`
- `adc_data[15:0]`
- `adc_of`

Add a new module, `adc_capture_axis.v`, between `LTC2208.v` and the FIFO.

### 2.3 adc_capture_axis Contract

Minimum ports:

```verilog
module adc_capture_axis #(
    parameter integer MAX_FRAME_LEN = 16384
)(
    input  wire        adc_clk,
    input  wire        rst_n,

    input  wire signed [15:0] adc_sample,
    input  wire        adc_overflow,

    input  wire        ctrl_start,
    input  wire        ctrl_abort,
    input  wire [15:0] ctrl_frame_len,
    input  wire [31:0] ctrl_frame_id,

    output reg         status_busy,
    output reg         status_done,
    output reg         status_error,
    output reg         status_overflow_seen,
    output reg         status_backpressure_seen,
    output reg         status_tlast_seen,
    output reg [15:0]  status_sample_count,
    output reg [31:0]  status_frame_id,

    output reg signed [15:0] m_axis_tdata,
    output reg         m_axis_tvalid,
    input  wire        m_axis_tready,
    output reg         m_axis_tlast,
    output reg         m_axis_tuser
);
```

State machine:

```text
IDLE:
  Wait for ctrl_start.
  Latch frame_len and frame_id.
  Clear done/error/status counters.

CAPTURE:
  Emit one ADC sample per accepted AXIS beat.
  Increment sample_count only when tvalid && tready.
  Assert TLAST only on sample_count == frame_len - 1.
  Track overflow/backpressure/error status.

DONE:
  Stop emitting tvalid.
  Hold status_done=1 and status_frame_id/sample_count for PS readback.
  Wait for clear/abort/next start.
```

Required rules:

- `m_axis_tvalid` is high only during `CAPTURE`.
- `m_axis_tlast` is high only on the last accepted sample.
- If `m_axis_tready=0`, hold current `tdata/tlast/tuser` stable and do not
  increment `sample_count`.
- If `adc_overflow=1`, set `status_overflow_seen=1`; PS should discard the
  frame.
- If `m_axis_tready=0` during capture, set `status_backpressure_seen=1`; PS
  should discard the frame unless this behavior is later explicitly accepted.
- If `frame_len == 0` or `frame_len > MAX_FRAME_LEN`, reject the request and set
  `status_error=1`.

### 2.4 FIFO Sizing

Increase `axis_data_fifo_0` depth from `1024` to at least `16384` words.

Recommended options:

| FIFO depth | Capacity | Use |
| ---: | ---: | --- |
| 8192 words | 16 KB | Minimum useful depth, two 4096-sample frames |
| 16384 words | 32 KB | Recommended Stage-1 depth |
| 32768 words | 64 KB | Useful if BRAM budget allows |

For Stage 1, use `16384` words first. It is large enough for a controlled
capture window and keeps resource usage reasonable.

Because the current AXI DMA length width is 16 bits, a single SimpleTransfer
must stay below `65536` bytes. With 16-bit ADC samples, the practical maximum is
about `32764` samples per DMA request. Stage 1 should start with:

- `4096` samples for regression against the current behavior.
- `16384` samples for the first larger controlled-frame test.
- Optionally `32764` samples for maximum Simple DMA envelope testing.

### 2.5 PL Control Interface

Use a small AXI-Lite register block rather than trying to overload the existing
LTC2208 GPIO control pins. The control plane needs multiple readback fields and
sticky status flags.

Proposed minimum registers:

| Offset | Name | Direction | Meaning |
| ---: | --- | --- | --- |
| `0x00` | `CONTROL` | W/R | bit0 `start`, bit1 `abort`, bit2 `clear_status`, bit3 `soft_reset` |
| `0x04` | `STATUS` | R | bit0 `idle`, bit1 `busy`, bit2 `done`, bit3 `error`, bit4 `overflow_seen`, bit5 `backpressure_seen`, bit6 `tlast_seen` |
| `0x08` | `FRAME_LEN` | W/R | Requested ADC samples per frame |
| `0x0C` | `FRAME_ID` | W/R | PS-written frame ID |
| `0x10` | `SAMPLE_COUNT` | R | Accepted samples in the last frame |
| `0x14` | `DONE_FRAME_ID` | R | Frame ID latched by PL for the completed frame |
| `0x18` | `ERROR_CODE` | R | Last detailed error code |
| `0x1C` | `VERSION` | R | Capture-control IP version |

Suggested error codes:

| Code | Meaning |
| ---: | --- |
| `0` | No error |
| `1` | Invalid frame length |
| `2` | Start while busy |
| `3` | ADC overflow observed |
| `4` | AXIS backpressure observed |
| `5` | Abort requested |

### 2.6 PS Stage-1 Sequence

Add `pl_capture_control.c/.h` and wrap DMA capture with a verified PL capture
transaction.

Required sequence:

```text
1. pl_capture_abort()
2. pl_capture_clear_status()
3. pl_capture_set_frame_len(samples)
4. pl_capture_set_frame_id(next_frame_id)
5. dma_capture_reset()
6. dma_capture_start(samples * 2)
7. pl_capture_start()
8. wait for DMA done
9. wait for PL done
10. invalidate DMA buffer cache
11. read PL status
12. accept frame only if:
    - done == 1
    - error == 0
    - overflow_seen == 0
    - backpressure_seen == 0
    - tlast_seen == 1
    - done_frame_id == next_frame_id
    - sample_count == samples
```

For Stage 1, `dma_capture_start()` can remain SimpleTransfer-based, but it
should be called only after the PL capture block is configured and before PL
capture is started.

### 2.7 Stage-1 Acceptance Tests

1. `4096`-sample frame test:
   - DMA IOC interrupt occurs.
   - PL `done=1`.
   - `sample_count=4096`.
   - `tlast_seen=1`.
   - No overflow/backpressure/error.

2. `16384`-sample frame test:
   - Same checks as above.
   - Confirm no DMA error and no FIFO/backpressure flag.

3. Repeated-frame ID test:
   - Capture at least 100 consecutive frames.
   - Confirm `DONE_FRAME_ID` increments exactly as PS requested.
   - Confirm no stale frame is accepted.

4. Sweep integration smoke test:
   - Replace the current sweep DMA frame acquisition with verified capture.
   - Confirm normal RBW modes still produce valid points.

5. Narrow-RBW diagnostic test:
   - Run the known zero-span 10K RBW test at IF `40.000 MHz` and `40.100 MHz`.
   - Record whether controlled single frames change the residual behavior.

## 3. Stage 2: Continuous DMA / Ring Capture

### 3.1 Goal

Guarantee continuity between buffers for long observation windows, especially
for 100K/30K/10K/1K RBW modes where the DSP accumulation needs more samples than
one practical Simple DMA transfer can carry.

Stage 2 should remove the repeated stop/start SimpleTransfer gap:

```text
ADC continuous stream
  -> controlled/monitored AXIS stream
  -> AXI DMA Scatter-Gather ring
  -> PS consumes completed buffers
```

### 3.2 Why Stage 2 Is Needed

Stage 1 guarantees that each buffer is internally valid. It still cannot
guarantee that frame N and frame N+1 are adjacent in ADC sample time, because PS
still rearms Simple DMA between captures.

That is not enough for DSP paths that keep long filter state across buffers.
The 10K FIR decimator path is the main risk because it assumes continuous input.

### 3.3 Preferred Stage-2 DMA Strategy

Use AXI DMA Scatter-Gather mode with a ring of receive buffer descriptors:

- Configure S2MM SG in Vivado.
- Allocate at least 4 to 8 RX buffers in DDR.
- Each BD points to one fixed-size buffer, for example 4096, 8192, or 16384
  samples.
- Start the DMA ring once.
- Let PL stream continuously.
- PS processes completed BDs and returns them to the ring.

Recommended BD buffer size for first bring-up:

| BD samples | Bytes | Use |
| ---: | ---: | --- |
| 4096 | 8192 | Lowest-risk migration from current path |
| 8192 | 16384 | Fewer interrupts, still modest latency |
| 16384 | 32768 | Better throughput and lower interrupt load |

Start Stage 2 with `4096` or `8192` samples per BD, then increase after the ring
is stable.

### 3.4 PL Behavior in Stage 2

Two possible approaches:

1. Continuous stream mode:
   - `adc_capture_axis` stays enabled.
   - It emits continuous AXIS samples.
   - TLAST can be generated every `frame_len` samples for BD diagnostics.
   - PS no longer treats TLAST as the only proof of continuity; BD order and
     stream counters also matter.

2. Packetized continuous capture mode:
   - PL emits fixed-size packets continuously after `stream_enable`.
   - Each packet has a packet counter.
   - PS verifies packet counters across BD boundaries.

For debug quality, Stage 2 should add a monotonically increasing PL packet or
sample counter. Because the AXIS data width is currently only 16-bit ADC sample
data, the counter cannot be embedded without changing the data format. Prefer
exposing counters through AXI-Lite status first:

- `TOTAL_SAMPLE_COUNT_HI/LO`
- `PACKET_COUNT`
- `DROP_COUNT`
- `OVERFLOW_COUNT`
- `LAST_TLAST_COUNT`

If deeper validation is required, add a debug mode that packs metadata into a
wider stream format, but keep normal ADC data format unchanged for the first SG
bring-up.

### 3.5 PS Stage-2 Sequence

High-level PS flow:

```text
1. Configure PL stream mode and clear counters.
2. Reset and initialize AXI DMA SG RX ring.
3. Submit all RX BDs to hardware.
4. Enable PL stream.
5. Start DMA S2MM ring.
6. Poll/interrupt on completed BDs.
7. For each completed BD:
   - invalidate cache for that buffer
   - process or enqueue samples in order
   - return BD to DMA ring
8. On stop:
   - disable PL stream
   - stop DMA ring
   - read and report PL counters/errors
```

For sweep/phase-noise integration:

- Wide RBW modes can still use Stage-1 verified single-frame capture if desired.
- Narrow RBW modes should use Stage-2 ring capture when filter state must be
  preserved across buffers.
- If a mode still uses discontinuous Stage-1 frames, the PS DSP must reset or
  isolate long FIR/decimator state at each frame boundary.

### 3.6 Stage-2 Acceptance Tests

1. SG ring liveness:
   - DMA runs for at least 10 seconds without S2MM error.
   - Completed BD count increases.
   - PL `drop_count` and `overflow_count` remain zero.

2. Counter monotonicity:
   - PL sample/packet counters increase monotonically.
   - PS BD completion order is consistent.

3. Sustained throughput:
   - Verify stable operation at the ADC stream rate and selected BD size.
   - Confirm CPU has enough time to process or enqueue buffers.

4. DSP continuity:
   - Run the 10K RBW zero-span test.
   - Compare against Stage-1 and current SimpleTransfer results.
   - A large residual drop would support the cross-buffer discontinuity
     hypothesis.

### 3.7 Current Stage-2 Bring-Up Steps

Use a two-step PS migration before changing the production measurement logic:

1. Add a SG-compatible receive layer in `dma_capture.c`.
   - If hardware reports Simple mode, keep using `XAxiDma_SimpleTransfer`.
   - If hardware reports SG mode, make `dma_capture_start()` submit one RX BD
     so existing sweep/background capture still works after the BD change.
   - Recreate the RX BD ring after each DMA reset.

2. Add a hidden SG smoke command for multi-BD continuity testing.
   - Command `0x14` takes `samples_per_bd` and `bd_count`.
   - PS submits `bd_count` RX BDs before enabling the PL stream.
   - PL emits one continuous stream window of `samples_per_bd * bd_count`
     samples, with TLAST only at the end of the whole window.
   - Acceptance condition: all BDs complete in order, completed byte count is
     at least the requested byte count, PL packet/sample counters are sane, and
     no overflow/backpressure/DMA error is reported.

Host-side smoke command:

```powershell
python tools\capture_stream_smoke_test.py --port COM7 --baud 921600 --mode sg --samples-per-bd 4096 --bd-count 4 --timeout 5
```

Before the Vivado SG change, this command is expected to return
`UNSUPPORTED`. After enabling AXI DMA SG and exporting/rebuilding the BSP, it
should return `OK`.

## 4. Implementation Order

Recommended order:

1. Add `adc_capture_axis.v`.
2. Refactor or bypass the current free-running AXIS output in `LTC2208.v`.
3. Insert `adc_capture_axis_0` in BD between `LTC2208_0` and `axis_data_fifo_0`.
4. Increase `axis_data_fifo_0` depth to `16384`.
5. Add AXI-Lite capture-control registers.
6. Add PS `pl_capture_control.c/.h`.
7. Wrap current Simple DMA acquisition with Stage-1 verified capture.
8. Validate 4096 and 16384 sample frames.
9. Integrate Stage-1 into sweep and phase-noise capture paths.
10. Add the PS SG-compatible receive layer and SG smoke command while current
    hardware is still Simple mode.
11. Convert AXI DMA S2MM to SG/ring mode in Vivado and export/rebuild BSP.
12. Validate existing sweep still runs through the one-BD SG compatibility
    path.
13. Validate multi-BD SG smoke with `4x4096`, then `2x8192` if stable
    because the current PL capture window is capped at `16384` samples.
14. Integrate SG/ring capture into narrow-RBW measurement paths.

## 5. Decision Rules

- Do not pass a DMA buffer to DSP unless Stage-1 status validation succeeds.
- Do not carry long FIR/decimator state across separate Stage-1 captures unless
  that discontinuity is explicitly part of the algorithm.
- Do not treat DMA IOC as a data-valid proof by itself; data is valid only after
  PL status and PS frame checks pass.
- Do not start Stage-2 SG/ring migration until Stage-1 can repeatedly produce
  verified frames.

## 6. Expected Outcome

After Stage 1, each DMA buffer should be complete and trustworthy.

After Stage 2, narrow-RBW measurements should have a path where long DSP state
can be applied to genuinely continuous samples instead of stitched-together
SimpleTransfer blocks.
